# utf8dok-authored ASG fixtures (NON-official)

These `*-input.adoc` / `*-output.json` pairs are **authored by the utf8dok
project**. They are **not** part of the official Eclipse AsciiDoc TCK.

They cover constructs the official suite (vendored under `tests/tck/`) does not
yet exercise — currently **block-level inline markup** (a paragraph containing a
constrained strong span), including a span on a multi-line paragraph.

## Why these exist

The official TCK has no fixture with inline markup inside a block paragraph, so
there is no authoritative expected ASG to vendor for that case. To still get
regression coverage, these fixtures are derived as follows:

- **Node shapes** are composed from the official fixtures: the `paragraph`/`text`
  shapes from `tests/tck/block/paragraph/*`, the `span` shape from
  `tests/tck/inline/span/strong/*`, and the multi-line-text rule (a text run
  spanning a `\n` is one node) from `tests/tck/block/paragraph/multiple-lines`.
- **Expected output** was generated by the `utf8dok asg` adapter and then
  hand-verified column-by-column against those official shapes.
- Every output is additionally validated against the authoritative ASG JSON
  Schema (`tests/schema/asg-schema.json`) by the same harness.

These are therefore **regression + schema-conformance** tests, not external
compliance proof. If the official TCK later adds equivalent fixtures, prefer
those and retire the overlap here.
